The user authorized fixing the findings in `QA-REVIEW-2026-11-10.md` and explicitly requested preserving the sorting icon. That icon's SVG was compared with the preceding production version and is identical.

## Changes

- Map collisions now merge complete source membership into a visible clickable group or landmark badge. Counts are conserved instead of hiding individual pins. Price labels shrink to dots where necessary. Pins at map edges or behind controls are offset onto exposed map space; covered reference icons cannot absorb hidden counts. Fully covered mobile maps do not draw exposed pins. Existing marker buttons are reused across redraws.
- Group selection resolves all cluster leaves, replacing the previous 100-leaf cap. Source cluster counts and co-located listing counts retain their separate meaning.
- Both account/admin Google sign-in buttons load Google's SDK with the selected `hl` locale and render with the same locale. Language changes serialize SDK loads, and old login callbacks remain rejected by the existing epoch guard. Failed SDK loads remain retryable. No authentication policy, server session or account data was changed.
- The actual land-area slider, numeric-input and histogram labels now use translated `área del terreno` copy. ES/EN changes remain reversible.
- Photo-tour sections, photo totals, hero actions and labels handle singular photo counts.
- The empty Saved message distinguishes no saved properties from existing favorites excluded by filters.
- Quick filters show small directional controls only when the row overflows. They respond to scroll, resizing and translated button widths.
- General result counts say `propiedad/propiedades`. The default sort choice is `Variado / Mixed order`; the existing session-varied behavior and sorting icon are unchanged.
- Updated cache versions cover the homepage, property detail, buyer preview and both portal entry points.

No API redeployment is required; this is a frontend change. No listing, account, contact or DNS data was modified.
