# Broker offer notifications and collection previews

New submissions from shared listing forms send a brief email to the broker's account address with the public property title, offered amount, and a link to `/cuenta/#ofertas`. The offer is saved before attempting email. A conditional notification claim and a stable Resend idempotency key prevent simultaneous submissions from sending duplicate notices. Delivery is tried twice; if both attempts fail, the offer remains available and a replay of that submission can retry delivery. There is no scheduled delivery worker. Historical submissions without notification state never send retroactive mail. Buyers keep the existing confirmation and private receipt; their contact details and receipt links are not included in broker notifications.

The account page opens Offers after successful sign-in for the notification link, including the normal password/rules gates, with one inbox refresh. Its entry module has a new cache version for returning browsers.

Public collection URLs now return the normal explorer with server-rendered sharing metadata: broker name, canonical collection URL, description, and a 1200 × 630 image. Images come only from that collection's public listings. Collections with real inventory never use a demo cover; demo-only collections retain their disclosure. Empty collections use the existing placeholder. Unknown collections return 404 and storage failures return 503. The matching image route and function source files are included in Vercel configuration.

Local validation: all 411 tests pass, the build succeeds, and `git diff --check` is clean. Coverage includes concurrent retries, email outages, historical submissions, notification privacy/escaping, account navigation, collection scope, missing collections, and image failure behavior. Mail tests use a stubbed transport; no production offers or test customer emails were created.
