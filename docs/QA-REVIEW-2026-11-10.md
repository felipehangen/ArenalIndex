## Findings and priorities

| Report item | Assessment | Evidence / next correction |
| --- | --- | --- |
| Missing map representation | **Confirmed; highest priority before launch.** | `site/index.html:286` hides colliding single-property markers without transferring their membership/count to a visible cluster. Executing the actual `drawMarkers()` function with two distinct nearby in-viewport listings produced two markers, one hidden, with only one listing represented visibly. This independently reproduces the underlying bug; the exact 32-to-28 and 6-to-4 screenshots were supplied by the external reviewer. Keep every visible-area listing accessible through a pin or correctly counted clickable group. |
| Google sign-in remains Spanish in English UI | **Confirmed visual mismatch in supplied screenshot; exact runtime cause still needs browser verification.** | Both portals share `site/admin/controller.mjs`. It already passes the selected language as `renderButton`'s `locale` at line 108 and redraws after language changes, so Spanish is not simply hard-coded there. The library is loaded without an `hl` parameter; [Google's locale reference](https://developers.google.com/identity/gsi/web/reference/js-reference#locale) also documents this parameter. Verify initial English load and both switch directions with the real Google widget. The report did not establish that authentication fails. |
| Spanish land-area accessibility labels in English | **Confirmed.** | Actual translation calls left all three reported labels unchanged. `site/index.html:300` uses `tamaño del terreno`, while the dictionary has older `tamaño` / `área del terreno` variants. Fix slider, numeric-input and histogram names together and verify reversible translation. |
| “1 fotos” | **Confirmed; minor copy issue.** | Gallery navigation and section counts at `site/property-detail.js:121` and `:124` unconditionally use the plural. Provide singular/plural forms in both languages. |
| Empty Saved view mentions filters | **Confirmed; minor copy issue.** | `site/index.html:239` uses the filtered-empty message for every empty Saved result. Distinguish nothing saved from saved listings excluded by current filters. |
| Last quick filter clipped | **Confirmed presentation issue in the screenshot.** | The row deliberately supports horizontal overflow; the option is not absent. Make overflow discoverable, e.g. an overflow-only end arrow, without adding a permanent extra toolbar. Desktop CSS has a thin scrollbar, but this may not be visible with system overlay-scrollbar settings. |
| “terrenos” and default “Explore” sort | **Mixed.** | Result and group counts still call all properties `terrenos`, even when they include buildings; use `propiedad/propiedades`. “Explore” is an accepted session-varied order, not a broken sort. A clearer sort-specific label such as `Variado / Mixed order` is a copy choice; do not imply an editorial recommendation or change its ordering behavior accidentally. |
